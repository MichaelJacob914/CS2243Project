# Report assets

Figures, figure data and rollout videos for the adaptive-step DSRL report page. Everything under
`report/assets/` is generated by two scripts and can be deleted and rebuilt.

```
report/assets/
  figs/<figure>.svg, figs/<figure>.png   scripts/plots.py (PNG is 2x: 192 dpi)
  data/<figure>.json                     the numbers drawn in each figure (for exact-value tables)
  videos/<task>__<method>__<success|fail>__<seed>.mp4
  videos/manifest.json                   one entry per clip
  videos/rollout_stats.json              per (task, method): success over all N rendered episodes
```

## Figures

Pure matplotlib from CSV/JSON/npz, so it is fine on a login node:

```bash
source .venv/bin/activate
python scripts/plots.py --runs_root logs/adsrl --out report/assets/figs
python scripts/plots.py --only fig4_curves,fig5_summary          # a subset
python scripts/plots.py --runs_root <scratch>/adsrl --out report/assets/figs   # runs written to scratch
```

Inputs (wandb is never read):
- `<runs_root>/<task>/<run>/eval_summary.csv`, `run_info.json`, and `eval_rollouts/step_*.npz` (from `train_adsrl.py`);
- `results/authority/*.json` (from `scripts/authority.py`);
- `results/base_eval*/<task>_K*/result.json` (from `scripts/base_eval.py`, pooled over eval seeds);
- optionally `notes/dppo_reference.csv` (`task,env_steps,success`).

Each figure function prints `[skip] <name>: missing ...` and writes nothing when its inputs don't exist
yet, so rerun the same command as runs finish. Defaults:
- Final success is the last deterministic eval (`--eval_mode det`) of runs that reached `train.total_timesteps`.
- "Best fixed k" is the k>0 with the highest mean final success (an oracle).
- "Adaptive k" means ρ=0.5 with all k allowed.

| Figure | Function | Needs |
|---|---|---|
| `fig_base_success` | base success per task (K=8/8/20), ±1 binomial SE | base eval (available) |
| `app_transport_ddim` | transport base success vs DDIM K | base eval (available) |
| `fig3a_authority` | action std over w and ‖a − a_base‖ vs k/(K−1), one line per task | authority JSON (available) |
| `fig2_sweep` | final success and steps to 80% of best vs k | finished fixed-k runs |
| `fig3bc_distance` | ‖a − a_base‖ at convergence vs k; control strength vs success | finished fixed-k runs + final npz |
| `fig4_curves` | success vs env steps, mean ± SE over seeds | any runs |
| `fig5_summary` | final success, normalized AUC, success vs GPU-hours | finished runs |
| `fig6_k_usage` | k frequencies over training; P(k \| episode time) | adaptive runs with npz dumps |
| `fig7_ablations` | Δ success vs adaptive k (k subset, ρ=0.25) | adaptive + ablation runs |
| `app_perk_curves`, `app_k_entropy`, `app_stability`, `app_ep_len` | appendix | runs |

Colors are fixed in `METHOD_COLORS` at the top of `scripts/plots.py`:
- Adaptive k is the only saturated color (orange `#e8590c`).
- DSRL is neutral dark (`#2e2e2c`).
- The other methods are muted (best fixed k teal, residual SAC plum, uniform-random k light gray dashed).
- The base policy is a gray dashed reference line.
- Task colors (blue / green / amber) only appear in figures that have no methods (Fig 3).

Optional QA, as used for the current figures: write PDFs and run the nature-figure alignment gate.

```bash
NATURE_FIGURE_SCRIPTS=~/.claude/skills/nature-figure/scripts \
  python scripts/plots.py --qa_dir <scratch>/qa
```

## Videos

Rendering needs EGL, so it only runs on a GPU node. `scripts/slurm/render_base.sbatch` renders the base
policy for all three tasks (about 5 min on one H100):

```bash
sbatch scripts/slurm/render_base.sbatch
```

### Naming

`<task>__<method>__<success|fail>__<seed>.mp4`, where:
- `task` is one of `can`, `square`, `transport`;
- `method` is one of:
  - `base`;
  - `dsrl` (fixed k=0);
  - `k<K>` (other fixed k);
  - `adaptive`;
  - `uniform_k` (`steer.freeze_k_uniform`);
  - `adaptive_subset` (`steer.k_subset`).
- `seed` sets the initial state (`np.random.seed(seed)` before `env.reset()`) and the per-chunk x_T stream.

Each (task, method) runs `--n_episodes` (default 10) on seeds `seed0..seed0+N−1` (default 0–9). It keeps
the first 2 successes and the first 2 failures in seed order. The same seed gives the same initial state
for every method; `init_state_hash` in the manifest lets you check this.

Clip format:
- H.264, yuv420p, 20 fps (the robosuite control rate), `+faststart`.
- Each camera is 256×256 under a 48 px header, cameras side by side, so clips are 512×304.
- Cameras: agentview + wrist camera for can/square, and agentview + frontview for transport (agentview
  only shows part of the transport scene). Override with `--cameras agentview`.
- A clip stops 30 env steps (1.5 s) after success; failures run the full horizon.
- The header shows task, method, chunk index and the k used for the current chunk. Adaptive runs also get
  a π(k|s) bar chart with the chosen k in orange. A green "✓ success @ step N" badge appears once the task
  succeeds.
- Success follows the eval protocol in `train_adsrl.py`: a chunk succeeds when
  Σ(r − 1) > −1 over its env steps, and `steps_to_success` = (first successful chunk + 1) × act_steps.
- Base-policy clips are 0.2–0.6 MB, well under the 2 MB budget.

`manifest.json` entries contain: `file`, `task`, `method`, `seed`, `success`, `episode_length`,
`steps_to_success`, `k_sequence` (one per chunk; null for the base policy), `init_state_hash`, `size_bytes`,
`duration_s`, `n_frames`, `codec`, `pix_fmt`, `cameras`, `ddim_steps`, and `ckpt`. Rerunning a
(task, method) replaces the entries for files with the same name. Delete stale clips by hand if the seed
set changes.

### Clips for trained runs

Run these on a GPU node. Pass the checkpoint that `train_adsrl.py` saves: `<logdir>/checkpoint/final.pt`,
or `latest.pt` while a run is still training. The run config is read from `<logdir>/run_info.json`, so K,
the network sizes and the steering mode always match training. The replay buffer is not loaded.

```bash
# interactive
srun -p kempner_h100 --account kempner_pehlevan_lab --gres=gpu:1 -c 8 --mem 32G -t 00:30:00 --pty bash
source .venv/bin/activate; export MUJOCO_GL=egl PYOPENGL_PLATFORM=egl

# DSRL (k=0) and a fixed k
python scripts/render_rollouts.py --task can --policy fixed_k --k 0 --ckpt logs/adsrl/can/<k0 run>/checkpoint/final.pt
python scripts/render_rollouts.py --task can --policy fixed_k --k 3 --ckpt logs/adsrl/can/<k3 run>/checkpoint/final.pt

# adaptive k (also used for uniform-random k and k-subset runs; the method slug comes from the config)
python scripts/render_rollouts.py --task can --policy adaptive --ckpt logs/adsrl/can/<adaptive run>/checkpoint/final.pt

# transport: K comes from the run config (20 if trained with model.ddim_steps=20)
python scripts/render_rollouts.py --task transport --policy adaptive --ckpt logs/adsrl/transport/<run>/checkpoint/final.pt
```

By default actions are deterministic (argmax k, mean w), matching the `det` eval. Pass `--stochastic` to
sample (k, w) instead. To render several runs in one allocation, launch the commands as background
processes and `wait`, as `render_base.sbatch` does. This is safe because the manifest writes are
file-locked.

### Caveat: reproducibility

Methods share initial states and x_T streams, but a long rollout is not bit-reproducible across runs.
Transport seed 0 for the base policy:
- succeeded at step 616 in two separate agentview-only runs;
- failed in the two-camera run.

Small numerical differences (most likely GPU nondeterminism in the policy) compound over 800 steps; the
cause has not been isolated. The success rate in `rollout_stats.json` covers only 10 episodes, so it is
illustrative. Use `results/base_eval*` (200–600 episodes) for the numbers.
