# Experiment: Adaptive-step DSRL on Furniture-Bench (one_leg, lamp, round_table; low randomness)
Status: Paused — sweep cancelled 2026-11-07 (user switched to the π0/LIBERO direction)

## Goal
Repeat the full study (fixed-step sweep, adaptive step, random step, residual RL, constant-noise CEM) on three high-precision assembly tasks, where steering at a later denoising step (small, precise corrections) is most likely to beat DSRL (k=0).

## Decisions (user, 2026-11-06)
- Tasks: one_leg_low, lamp_low, round_table_low (DPPO Furniture-Bench, IsaacGym, state obs 58-dim, action 10-dim, act_steps 8, 700-step episodes, sparse reward).
- One seed per condition (no 3-seed follow-ups).
- Many parallel GPU envs (DPPO used 1000), with fewer gradient updates per env step than robomimic. This is a different sample-efficiency regime from can/square/transport; compare methods within a task, not env-step budgets across task families.

## Setup (planned)
- Base policies: DPPO pretrained diffusion MLP, ta8 / td100 (`*_low_dim_pre_diffusion_mlp_ta8_td100/.../state_8000.pt`, via `dsrl/dppo/script/download_url.py`), same family as the robomimic base policies. Normalization from DPPO_DATA_DIR/furniture/<task>_low/normalization.pth.
- Environment: separate uv venv `.venv-furniture` (Python 3.8; IsaacGym Preview 4 + ankile/furniture-bench fork, per `dsrl/dppo/installation/install_furniture.md`). Our `adsrl/` code must run unchanged on 3.8.
- Env adapter: DPPO's `FurnitureRLSimEnvMultiStepWrapper` (GPU-batched, torch tensors) → SB3 VecEnv + x_T augmentation. IsaacGym allows one sim per process, so evals run deterministic episodes on the same env (or a dedicated sub-batch), not a second env.
- DDIM K: chosen like transport — base success at K ∈ {100, 20, 10}; smallest K within ~5 pts of K=100.
- Conditions per task (1 seed): fixed k on an 8-point grid under K (k=0 = DSRL), adaptive ρ=0.5 (actor restricted to the same 8-point grid via `steer.k_subset`, ~2.5× cheaper than scoring all K), random k (same grid), residual SAC β=0.3, constant-noise CEM. 12 runs/task, 36 total.
- Metrics: as before — det eval success vs env steps (mean of last 3 evals), normalized AUC, env steps to 80% of best, success vs GPU-hours, ‖a − a_base‖, k usage over training.
- Hardware: kempner_h100, kempner_pehlevan_lab, MPS packs if IsaacGym tolerates several processes per GPU (pilot decides).

- **Adapter** `adsrl/furniture_env.py` → `FurnitureVecEnv` (SB3 VecEnv over one batched `FurnitureRLSimEnv`, same sim args as DPPO's `make_async`). Obs/action processing copied from DPPO's `FurnitureRLSimEnvMultiStepWrapper` (6D rotation, min-max normalization, clamp ±5). Reward/episode semantics copied from the robomimic pipeline: per sim step `1[all parts assembled] − 1` summed over the 8-step chunk (assembled flag is FurnitureRLSimEnv's sticky `already_assembled`), success does not end the episode, fixed-length episodes with timeout = terminal (as `ActionChunkWrapper`). All envs run in lockstep (`ceil(max_episode_steps/8)` chunks: one_leg 88, lamp/round_table 125) and reset together, as in DPPO (lamp's bulb logic assumes synchronized env_steps). Intermediate parts (lamp/round_table have 2 pairs) give no reward — same as robomimic transport's final-success-only reward.
- **Eval on the shared sim**: `env.env_type: furniture` makes `train_adsrl.py` use the training env as eval env. `eval_interval` must be a multiple of the episode length, so evals start at an episode boundary; each eval runs `num_evals / n_envs` (default 1) full lockstep deterministic episodes with the policy frozen, then the env is reset and SB3's next obs is replaced in place. Eval env steps are not counted in the budget (as for robomimic's separate eval envs). Furniture configs skip the stochastic eval (`stochastic_eval: False`; `train/success_rate` already reports the stochastic policy on full episodes).
- **train_adsrl.py changes** (robomimic paths unchanged, verified by an orig-vs-new diff run, see log): `import isaacgym` before torch if installed; `env_type` switch; furniture sim created before CUDA init; new optional keys `stochastic_eval` (default True), `log_train_stdout` (default False: `[init]`/`[train]`/`[eval]` timing lines); `run_info.sb3_path`.
- **Configs** `cfg/adsrl/{one_leg_low,lamp_low,round_table_low}.yaml` (from transport.yaml): DPPO furniture network (7×1024 MLP, cond_mlp [512, 64], layernorm), eval every 10 episodes, `init_rollout_steps` = 1 episode, `buffer_size` 2M, `checkpoint_every_min` 120. n_envs / utd / total_timesteps / ddim_steps are placeholders until the pilot below.
- **Corrections to the plan**: lamp/round_table obs are 44-dim (16 robot + 4 parts × 7), not 58; their episodes are 1000 steps (125 chunks); one_leg is 700 steps (88 chunks).
- **Hardware**: one_leg on kempner_h100; lamp/round_table must run on A100 (`-p kempner`) because of the H100 PhysX crash. 1 run per GPU (MPS crashes IsaacGym). gymtorch is JIT-built once into `third_party/torch_extensions/` (needs `scripts/furniture/env.sh`).
- **Scripts**: `scripts/furniture/env.sh` (source before any furniture run), `scripts/furniture/base_eval_furniture.py` (base success per K), `scripts/slurm/exp6_pack.sbatch` (MPS pack of train_adsrl runs; `SEQ=1 RUN_SEC=…` runs them one after another for throughput timing). Tests: `tests/test_furniture_env.py` (fake sim; shapes, reward/success, lockstep auto-reset, action denormalization, x_T augmentation).

## Analysis
- **Sim-bound regime.** The IsaacGym sim dominates: ~1.6 s per 1024-env chunk on H100, and larger batches amortize it (n=2048 is 1.55× the env throughput of n=1024; n=256 is 0.41×). Gradient steps are cheap in comparison (~31–37 ms), so wall-clock is set by `sim + utd × 35 ms` per vec step.
- **No GPU packing.** MPS crashes IsaacGym; time-slicing gives no gain. One run per GPU.
- **Hopper bug.** lamp/round_table hit a PhysX GJK/EPA kernel failure on H100 at any batch size; they run on A100 (`kempner`). one_leg runs on H100.
- **Early collapse of k0 DSRL.** With few updates per transition, the actor drives the noise to the box edges before the critic is fit (|a−a_base| grows, success falls). Robomimic showed the same early phase (transport k0 det eval stayed ≤ 0.02 for ~0.5M updates before rising; can k0 needed ~60k updates to reach 0.31). So a 1-h check cannot confirm improvement at these update rates; LC3 (~18 updates/s) reaches ~100k updates after ~1.6 h, and LC4 tests whether the noise trust region prevents the collapse.
- **Residual β=0.3 is too large here** (base success 0.44 → 0.00 with the untrained residual actor).
